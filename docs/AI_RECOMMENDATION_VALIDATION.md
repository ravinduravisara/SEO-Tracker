# AI Recommendation Verification Engine Specifications

## 1. Overview
The Recommendation Verification Engine (`backend/ai/recommendation_validator.py`) acts as an immutable algorithmic firewall between generative AI output and client-facing SEO reports. Every candidate recommendation generated by Gemma 4 must satisfy rigorous evidence and accuracy tests.

---

## 2. Mandatory Verification Rules

### Rule 1: Audit Telemetry Grounding (Issue ID Verification)
* **Check**: The recommendation must cite an `issue_id` (e.g. `T04`, `O01`, `C02`) that genuinely triggered during the audit.
* **Failure Condition**: Hallucinated issues or unsolicited advice are marked `REJECTED` with reason `"Issue identifier not found in verified audit telemetry"`.

### Rule 2: Target Domain Boundary Enforcement
* **Check**: The `affected_url` must belong to the audited target domain or authorized subdomains.
* **Failure Condition**: Any recommendation pointing to an external website or unmeasured third-party domain is immediately dropped.

### Rule 3: Contradiction Detection (Measured Facts vs Claims)
* **XML Sitemap Contradiction**: If the audit measured `sitemap.found == True` or `sitemap_present == True`, any recommendation claiming the site "lacks a sitemap" or "needs an XML sitemap generated" is marked `REJECTED`.
* **Robots.txt 404/410 Handling**: If robots.txt returned HTTP 404 or 410, any advice claiming this is a "severe ranking penalty" or "critical failure" is marked `REJECTED` (Googlebot crawls without restrictions when robots.txt is 404).
* **Missing Canonical Tag Grading**: Missing self-referencing canonical tags must be graded as optimization recommendations (`WARN`), not automatic critical failures.

### Rule 4: Prohibition of Fabricated Search Volume & KD
* **Check**: If third-party keyword data integrations (DataForSEO or Google Search Console) are inactive, the AI must NOT invent specific numerical monthly search volume numbers or keyword difficulty percentages.
* **Failure Condition**: Advice citing invented search numbers without a verified data provider is marked `REJECTED`.

### Rule 5: Prohibition of Guaranteed Rankings
* **Check**: Matches against prohibited claim regexes:
  * `guarantee(?:s|d)?\s+(?:.*)?(?:first\s+page|top\s+rank|#1\s+position|#1\s+ranking|#1|ranking|traffic)`
  * `will\s+rank\s+(?:#1|first|number\s+one)`
  * `guaranteed\s+(?:traffic|rankings?|results?)`
  * `100%\s+indexing\s+guarantee`
* **Failure Condition**: Marked `REJECTED` with reason `"Recommendation makes prohibited, unsupportable claims of guaranteed Google rankings"`.

---

## 3. Output Schema & Traceability
All rejected recommendations are logged in `ai_recommendation_records` with their exact rejection reason for audit traceability and continuous fine-tuning feedback.
